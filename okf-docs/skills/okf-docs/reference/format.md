# Format

OKF v0.2 plus a few extension keys. OKF itself requires one thing per file: frontmatter with a non-empty `type`. The rest is house style that makes bundles rankable and checkable. Other OKF tools ignore the extensions.

## Bundle

```
<bundle>/
├── index.md        # listing; generated by `okf.py index --write`
├── log.md          # change history, newest date first; written by `okf.py log`
└── <folder>/
    ├── index.md
    └── <concept>.md
```

- `index.md` and `log.md` are reserved at every level. Only the bundle-root `index.md` has frontmatter, and only `okf_version: "0.2"`.
- Every other `.md` file is a concept and needs frontmatter. No `README.md` inside a bundle; `index.md` is the entry point.
- Create a folder only when a file goes in it. Folder entries in an index carry a one-line description you write; the script keeps it.
- Names: `kebab-case.md`. Decisions: `NNN-short-title.md`, three digits. Observations and assets start with their date: `YYYY-MM-DD-slug.md`.

## Frontmatter

```yaml
---
type: concept
title: Data export
description: Export a workspace as CSV or JSON; runs as a background job, 500 MB limit.
tags: [export, jobs]
scope: acme-api/export
specificity: specific
credibility: reported
generated:
  by: okf-docs/0.9.1
  at: 2026-11-12T14:03:22+01:00
verified:
  - by: human:alex
    at: 2026-11-12T16:40:00+01:00
sources:
  - id: job
    resource: ../../src/export/job.ts
  - id: d004
    resource: ../decisions/004-export-format.md
---
```

| Key | From | Rule |
|---|---|---|
| `type` | OKF, required | Lowercase house type from the bundle's kind file. Any string is valid OKF |
| `title` | OKF | House: required |
| `description` | OKF | House: required. One sentence with the most useful fact, never "This document describes…". Feeds `index.md` |
| `resource` | OKF | Canonical URI of the thing described (endpoint, table, repo), when there is one |
| `tags` | OKF | Only tags someone would filter by |
| `sources` | OKF | List of entries, each with `resource` (path or URL) and an `id` when the body cites it |
| `generated` | OKF | `by` and `at` of the last meaningful change. Bump `at` when facts change, not for typo fixes |
| `verified` | OKF | List of `by` and `at` entries: who confirmed the current content. Remove entries when facts change unless the confirmer re-checked |
| `status` | OKF | `deprecated` when kept only for links or history. Absent means current. Don't write `draft`: a file with no human `verified` entry is unreviewed, and a second marker can disagree with it. Keep `draft` where another tool set it, and remove it when a human verifies the file |
| `stale_after` | OKF | Absolute instant after which the content is stale: an offer valid to a date, an observation to re-check |
| `scope` | extension | The subject, broad to narrow, `/`-separated (`acme-api/export`). Absent means the bundle's root scope from config. The parent of `a/b` is `a` |
| `specificity` | extension | `general` (a whole product or area), `specific` (one feature or process), `exact` (one limit, field, endpoint or rule). Scope fit, never length |
| `credibility` | extension | Where the content comes from: `reported` (what a source or person stated) or `inferred` (your conclusion from them). Set it on every file you write except assets. It records origin, not review, so it stays when someone verifies the file |
| `class` | extension, brain | `canonical`, `decision`, `observation`, `asset` or `reference` |
| `visibility` | extension | `internal` (default) or `public`. Only public files may feed public pages |
| `supersedes`, `superseded_by` | extension | Path of the replaced or replacing file. Decisions and deprecated files only |

Keep keys other tools added; never strip them.

## Values

- **YAML style:** mappings in block style, one key per line, as above. Inline lists only for plain words (`tags: [export, jobs]`). Older YAML parsers (libyaml before 0.2.2, which macOS's system Ruby still uses, and PyYAML before 5.1) reject a timestamp or `human:alex` inside `{ }` or `[ ]`; `okf.py check` warns about it.
- **Timestamps:** ISO 8601 with an offset: `2026-11-12T14:03:22+01:00` or `2026-11-12T13:03:22Z`. Use `NOW` from the context output or `okf.py now`. Never a bare date.
- **Actors:** `human:<id>` for a person, with the id that `okf.py now` prints (never guess one); `okf-docs/<version>` for what you write; `process:<id>` for automation.
- **Sources and footnotes:** cite a claim with a footnote whose label is the source `id`:

  ```markdown
  Exports over 500 MB fail with `EXPORT_TOO_LARGE`.[^job]

  [^job]: src/export/job.ts
  ```

  `resource` paths are relative to the file (`../../src/export/job.ts`) or URLs. A plain description such as `pasted in conversation, 2026-11-12` is allowed when there is no file. A source you only summarized needs an entry but no footnote.
- **Links:** relative paths (`../schema/exports.md`) by default, because they work on GitHub, in editors and in site generators. OKF also allows `/`-rooted links, resolved from the bundle root; set `links: rooted` in config to use them. Link another bundle by its URL from `related` in config.

## Reserved files

`index.md`:

```markdown
# Sections

* [Product](product/) - What it does: features, behavior, limits.

# Concepts

* [Data export](export.md) - Export a workspace as CSV or JSON; runs as a background job, 500 MB limit.
```

Entries come from each file's `title` and `description`. Regenerate with `okf.py index --write` rather than editing entries by hand; headings, order and folder descriptions you edit are kept.

`log.md`:

```markdown
# Directory Update Log

## 2026-11-12
* **Creation**: [Data export](product/export.md).
* **Deprecation**: [CSV export v1](product/csv-v1.md), replaced by [Data export](product/export.md).
```

Add entries with `okf.py log <bundle> <Kind> "<message>"`. Kinds: Initialization, Creation, Update, Deprecation, Deletion, Decision, Sync, Publication.

## OKF errors and house rules

`okf.py check` labels each finding:

- **OKF:** breaks the spec. Missing frontmatter or `type`, frontmatter in a non-root `index.md`, malformed timestamps, actors, `sources` or `verified`. Fix these first; other OKF tools may misread the bundle.
- **House:** this plugin's conventions. Titles and descriptions, naming, index coverage, extension values, link style.
- **Content:** broken links, stale or unverified files, duplicates, bloat, deletion candidates.

## Upgrading bundles from the v3 skills

The older standalone okf-docs and okf-company-brain skills wrote a v3 format. `okf.py upgrade --dry-run` lists the changes; run it without `--dry-run` once the user approves.

| v3 | Now |
|---|---|
| `at: 2026-09-05` | `at: 2026-09-05T00:00:00Z` |
| `by: agent` | `by: okf-docs/3` |
| `by: alex` | `by: human:alex` |
| `sources: [src/x.ts]` | Entries with `resource`, paths made relative to the file |
| `credibility: verified` | Removed where a human `verified` entry records the review. Without one, upgrade lists the file: ask who confirmed it, then add the entry or set `reported` |
| `credibility: reported` or `inferred` | Kept |
| `links: [...]` | Moved to a `## Related` list in the body |
| Frontmatter in folder `index.md` files | Removed |
| Promoted observations kept with `superseded_by` | Deleted after approval (check lists them) |
| A page in a folder's `index.md`, such as `products/waycam/index.md` | Moved to `products/waycam/waycam.md` after approval, with links repointed; then the index is rebuilt. upgrade, `check --fix` and `index --write` never rewrite such a file (check: `index-page`) |

The v3 rules also have to go, or Claude follows two formats. Context reports them as `LEGACY_SKILLS` (installed skills) and `LEGACY_RULES` (copies in the project's `.claude/skills/`, and `CLAUDE.md` or `AGENTS.md` lines such as "no `status` field" or `credibility: verified`). Propose retiring them in the same plan as the upgrade; change nothing before the user approves.
